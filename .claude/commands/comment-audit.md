# /comment-audit — 주석 사실 검증 (Phase × Batch)

코드베이스 전반의 주석을 **코드 사실과 대조**해 stale 마커, 시점/상태 박힌 outdated 주석, 코드와 불일치하는 주석을 식별한다. 주석이 가리키는 동작·엔티티·호출처가 실제로 존재하는지/유효한지 Grep·Read로 검증한다. **수정은 하지 않는다. 보고서만 산출.**

분량이 많으므로 Phase별로 결과를 디스크에 박제해 컨텍스트 컴팩트가 발생해도 직전 산출물만 있으면 재개 가능하다.

---

## 사용법

| 인자 | 동작 |
|---|---|
| `/comment-audit` | 신규 라운드 시작 — Phase 1~4 모두 자동 진행 |
| `/comment-audit resume` | `STATUS.md` 기준 미완료 Phase부터 재개 |
| `/comment-audit report` | Phase 4 합본 재실행 (REPORT.md 재생성) |
| `/comment-audit status` | 현재 진행 상태 출력 |

---

## 검증 대상 — 의심 패턴

다음 표현이 포함된 주석을 의심 후보로 추출하여 코드 검증:

| # | 분류 | 패턴 |
|---|---|---|
| 1 | 명시 마커 | `TODO`, `FIXME`, `HACK`, `XXX` |
| 2 | 날짜·시점 | `2025-`, `2026-`, `~월`, `~일`, `이번주`, `다음주`, `지난주`, `~시까지` |
| 3 | 임시 상태 | `임시`, `일단`, `당분간`, `지금은`, `현재까지`, `예정`, `추후`, `나중에`, `차후` |
| 4 | 폐기 표현 | `deprecated`, `legacy`, `레거시`, `구버전`, `더 이상`, `미사용` |
| 5 | 미정 / 경고 | `TBD`, `미정`, `검토 필요`, `확인 필요` |
| 6 | 버전 잔재 | `v1`, `v2`, `구 버전`, `이전 버전` |

위 패턴이 포함된 주석은 **시간/상태 의존**이라 코드 변경에 따라 stale 가능성 높음. 우선 검증.

---

## 핵심 원칙

1. **단계별 진행** — Phase 단위로 나눠 처리, 중간 결과는 디스크에 박제
2. **컨텍스트 컴팩트 회피** — 각 Phase 시작 시 직전 Phase 산출물(.md)만 Read. 누적 보존 금지
3. **모든 판정은 코드 사실 기반** — 주석 마커만 보고 단정 금지. Grep으로 메서드/엔티티/호출처 실재 여부 직접 확인. DEVNOTES 설계 결정 박제도 참조
4. **자동 수정 금지** — 모든 발견은 보고서로만 산출. 실제 수정은 사용자 승인 후 별도 작업
5. **자동 진행** — Phase 1~4 자동으로 이어짐. 사용자 보고는 Phase 4 최종 REPORT 한 번뿐. 컨텍스트 한계 도달 시 STATUS.md 박제 후 종료, `resume`으로 재개
6. **CLAUDE.md 한국어 주석 규칙 존중** — 의도/이유 설명 주석은 stale이 아니다. **시점/상태 표현이 박혀 있고 그 시점이 지났거나 상태가 변경된 경우만 stale 후보**

## Phase 구성

### Phase 1 — Map (자동 진행)

**목적**: 의심 주석 후보 전수 추출 + 분할 계획

**절차**:
1. `Glob`으로 `.cs`/`.razor`/`.razor.cs` 파일 식별
2. 자동 생성물 제외: `Migrations/`, `*.Designer.cs`, `AppDbContextModelSnapshot.cs`, `obj/`, `bin/`, `*.g.cs`, `GlobalUsings.cs`, `AssemblyInfo.cs`
3. `Grep`으로 §검증 대상 패턴 6종을 OR 결합한 정규식으로 일괄 검출 (멀티라인 포함)
4. 결과를 (file:line, 주석 원문, 의심 분류) 쌍으로 수집
5. 의심 후보 개수 기준 배치 분할 (1배치 = 10~15개)

**산출물**: `state/01-map.md`
```markdown
# Phase 1 Map

## 의심 패턴별 카운트
| 분류 | 건수 |
|---|---|
| 명시 마커 (TODO 등) | N |
| 날짜·시점 | M |
| 임시 상태 | K |
| 폐기 표현 | L |
| 미정·경고 | P |
| 버전 잔재 | Q |
| **합계** | **N+M+K+L+P+Q** |

## 의심 주석 전수 목록
- {file}:{line} — `{원문 발췌}` (분류: {임시/폐기/...})
- ...

## 분할 계획
- Phase 2 배치: B1 (1~15) / B2 (16~30) / ...
```

**완료 후**: 즉시 Phase 2로 자동 진행.

---

### Phase 2 — 의심 주석 정리 (배치 자동 반복)

**목적**: 각 의심 후보를 검증 가능한 항목으로 분해

**한 배치 처리**:
1. `01-map.md`의 해당 배치 후보 로드
2. 각 후보마다:
   - 주변 5~10줄 컨텍스트 Read
   - 검증할 사실 항목 명시 (예: "주석에 '#월 #일까지 임시 처리'라고 되어있음 → 그 임시 처리가 여전히 코드에 있는가? 정식 처리로 교체됐는가?")
3. 결과를 `state/02-suspect-{batch}.md`에 append

**산출물 형식**:
```markdown
# Phase 2 — 의심 주석 정리 (Batch {N})

## #{i} {file}:{line}
**원문**: `{주석 전체}`
**분류**: {임시/폐기/...}
**컨텍스트 발췌**: 
```cs
{주변 5~10줄}
```
**검증 항목**:
- {사실 1}: {확인 방법 — Grep 키워드, 관련 엔티티}
- {사실 2}: ...
```

**컨텍스트 관리**:
- 배치당 최대 10~15개 (검증 항목 정리만 하므로 가벼움)
- 모든 배치 완료 후 즉시 Phase 3 자동 진행

---

### Phase 3 — 코드 사실 검증 (배치 자동 반복)

**목적**: 각 의심 주석을 코드 분석으로 stale / Active / Outdated 판정

**한 후보 검증 절차**:
1. `02-suspect-{batch}.md`에서 검증 항목 로드
2. 항목별로:
   - 관련 메서드/엔티티/필드 Grep
   - 호출처·정의처·테스트 검색
   - 동작 흐름 Read (필요 시)
   - DEVNOTES.md `[설계 결정]` / `[기술 부채]` 박제 확인
3. 판정:
   - **Stale** — 주석이 가리키는 작업/상태가 이미 다른 방식으로 해결됨. 제거 또는 갱신 권장
   - **Active** — 여전히 유효한 미구현/임시/경고. 주석 그대로 유지
   - **Outdated** — 일부만 해결됨 또는 표현이 부정확. 보완 권장
4. 근거를 코드 위치(file:line)와 함께 기록

**산출물 형식**:
```markdown
# Phase 3 — 코드 검증 (Batch {N})

## #{i} {file}:{line}
**원문**: `{주석}`
**판정**: Stale | Active | Outdated

**근거**:
- {엔티티/메서드 검증 결과 — 실재 / 변경 / 제거 등}
- 관련 코드 위치: {file2}:{line2}
- DEVNOTES 박제: {있다면 §섹션 / 없으면 "없음"}

**권장 조치**: 제거 / 유지 / 갱신({신규 문구 제안})
```

**컨텍스트 관리**:
- 배치당 최대 5~10개 (검증당 다회 Grep/Read 발생)
- 컨텍스트 한계 임박 시 STATUS.md 갱신 후 종료
- 모든 배치 완료 후 즉시 Phase 4 자동 진행

---

### Phase 4 — 종합 보고서 (자동)

**목적**: Phase 3 모든 배치 결과를 통합 보고서로 합성

**절차**:
1. `state/03-verify-*.md` 모두 Read
2. 카테고리별 통합 정리
3. `state/REPORT.md` 작성

**산출물**:
```markdown
# Comment Audit Report

## 통계
- 의심 후보 전체 N건 / Stale K건 / Active M건 / Outdated L건

## Stale (제거 권장)
- {file}:{line} — `{원문}` → 사유 요약

## Outdated (갱신 권장)
- {file}:{line} — `{원문}` → 보완 제안

## Active (유지)
- {file}:{line} — `{원문}` (요약 1줄)

## 사용자 결정 필요 항목
- {모호한 사례}
```

**완료 후**: 사용자에게 통계 + Stale/Outdated 핵심 항목만 짧게 보고. 실제 수정은 별도 라운드.

## STATUS.md

```markdown
# Comment Audit Status

## 진행
- [x] Phase 1 Map (2026-05-09 14:00)
- [x] Phase 2 Batch 1 (2026-05-09 14:10)
- [ ] Phase 2 Batch 2
- [ ] Phase 3
- [ ] Phase 4 REPORT
```

각 Phase·Batch 완료 시 즉시 갱신. `resume`은 첫 미완료 항목부터 재시작.

## 컨텍스트 관리 체크리스트

- [ ] Phase 시작 시 직전 Phase 산출물(.md)만 Read. 그 이전 Phase 결과는 메모리에 유지하지 않음
- [ ] 배치 완료 즉시 결과를 .md에 저장. 다음 배치 진입 전 메모리 비움
- [ ] 한 번에 처리하는 후보 수 상한 준수 (Phase별 명시값)
- [ ] 컨텍스트 한계 임박 시 STATUS.md 갱신 후 종료. `resume`으로 재개

---

## 사용자 협업 프로토콜

- **자동 진행** — Phase 1~4 자동. 사용자 승인/보고 대기 안 함
- **유일한 사용자 보고**: Phase 4 최종 REPORT 통계 + 핵심 항목
- **자동 수정 금지** — 발견된 Stale 주석을 직접 제거하지 않음. 별도 수정 라운드에서 사용자 승인 후 진행

## 예외 처리

- 마이그레이션 자동 생성물 (`Migrations/`, `*.Designer.cs`, `AppDbContextModelSnapshot.cs`) — 검토 제외

- 빌드 산출물 (`bin/`, `obj/`, `*.g.cs`) — 검토 제외
- 자동 생성 GlobalUsings/AssemblyInfo — 검토 제외
- 테스트 코드 (`Framework.Tests/`) — 동일 규칙 적용
